**Input folder scanned:** `project/input_develop/`

**Recognized files in `project/input_develop/`:**
- `jira-*.md` — pre-fetched JIRA story details (summary, user story, acceptance criteria, technical notes). Generated automatically by `/use-raml-from-jira` or `/use-raml-to-exchange`. If absent, the agent will ask for a JIRA story ID to fetch and save it before generating.
- `confluence-design-*.md` — pre-fetched Confluence design (endpoints, request/response fields, downstream systems, HTTP status codes). Generated automatically by `/use-raml-from-jira` or `/use-raml-to-exchange`. If absent, the agent will ask for a JIRA story ID to fetch and save it before generating.
- RAML or OpenAPI spec (`.raml`, `.yaml`) — generated by `/use-raml-from-jira`; primary driver for Mule project scaffolding

**If context files are missing:** The agent will prompt you to provide a JIRA story ID so it can fetch and save them before generating.

**Fallback — if the folder was empty, provide one of:**
- Technical design document (`.md`, `.txt`) with flow logic and connector details
- Sample request/response payloads (`.json`) for DataWeave accuracy
- Describe requirements directly in chat

**Output will be written to:** `project/output_develop/`

> One agent per chat. Start a new chat with `/use-develop` for each new Mule application task.
> Store secrets in `~/.zshrc` and reference via `${VAR}` in Maven commands — never pass credentials directly.
