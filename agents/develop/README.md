# Develop Agent

Generates complete MuleSoft 4 applications from a RAML spec or technical design — including Mule XML flows, DataWeave transformations, global config, error handlers, property files, and POM — following Insulet implementation standards.

## Activate

Type `/use-develop` in a new Cursor chat.

## Folder Structure

```
develop/
├── rules/
│   ├── intent-gen-mule.mdc              ← main entry point
│   └── implementation-ruleset_v4.mdc   ← full Mule 4 generation standards
├── examples/                            ← Mule app templates and reference projects
├── templates/
│   ├── sf-http-sys-api-template/       ← HTTP listener system API template (add when available)
│   ├── mq-proc-api-template/           ← Anypoint MQ consumer process API template (add when available)
│   └── sf-pubsub-exp-api-template/     ← Salesforce Pub/Sub experience API template (add when available)
└── README.md
```

## Inputs → `project/input_develop/`

Place any of these before running `/use-develop`:
- RAML or OpenAPI spec (`.raml`, `.yaml`) — primary driver for endpoint contracts and data types
- `jira-{STORY-ID}.md` — JIRA story requirements, acceptance criteria, technical notes (auto-generated by `/use-raml-from-jira`)
- `confluence-design-{STORY-ID}.md` — endpoint definitions, field mappings, downstream system details, business rules, validations, HTTP status codes (auto-generated by `/use-raml-from-jira`)
- Technical design document (`.md`, `.txt`) with flow and connector details
- Sample payloads (`.json`) for accurate DataWeave transformations
- Flow/sequence/arch diagram as Mermaid code or an image (PNG, JPG, SVG) — optional; see below

The agent auto-generates `jira-*.md` and `confluence-design-*.md` when started from `/use-raml-from-jira`. These files are shared across agents — `/use-munit` and `/use-postman` both check this folder automatically to enrich their output.

### How business logic is consumed

The agent follows a **source precedence model** — it does not default to empty scaffolds when context is available:

| Source | Used for |
|--------|----------|
| Flow/sequence/arch diagram (if provided) | Orchestration shape and flow order — takes highest priority |
| `confluence-design-*.md` field-mapping tables | Populated DataWeave transforms (`p-*.dwl`, `v-*.dwl`) |
| `confluence-design-*.md` business rules | Conditional routing (`<choice>`), scope filters, state-update stubs |
| `confluence-design-*.md` field validations | `validate-input-sub-flow` raising `APP:BAD_REQUEST` |
| `confluence-design-*.md` HTTP status codes | Additional entries in `errors/customErrors.dwl` |
| `confluence-design-*.md` downstream systems | Connectivity configs and property keys per system |
| `jira-*.md` acceptance criteria | Inline comments in sub-flows confirming each AC is met |

**When no diagram is supplied** but Confluence/JIRA context files are present, the agent generates a Mermaid sequence diagram from the data-flow narrative and presents it for your approval before writing any XML or DWL.

**When both a diagram and Confluence files are present**, they are combined: the diagram drives orchestration structure; the Confluence text drives DataWeave expressions, validations, and error conditions.

If the folder is entirely empty, describe the requirements directly in chat.

## Handoff

Output project → use `/use-munit`, `/use-postman`, `/use-docs`, and `/use-review` in separate chats.

## Ruleset Standards (`implementation-ruleset_v4.mdc`)

Key standards enforced during generation:

| Area | Standard |
|------|----------|
| `mule-artifact.json` | `minMuleVersion: 4.9.0`, `javaSpecificationVersions: ["17"]`, no `secureProperties` when using Azure Key Vault |
| Property files | Required common keys: `timezone=EST`, `tier=Process`, `http.port`, `http.timeout`, `reconnection.frequency`, `reconnection.attempts`, `ie.resolvedFlag`, `ie.transactionType` |
| Health check messages | Lowercase values: `message.systemUp=up`, `message.systemDown=down`, `message.systemsAlive=alive`, `message.systemsReady=ready`, `message.systemsNotReady=not ready` |
| Logger | `logger.sensitiveKeyParts` — comprehensive 32-item PII list; `logger.safeKeys` — standard correlation IDs + app-specific non-PII entity IDs |
| Readiness DWL | `p-set-readiness-response-success.dwl` — scatter-gather payload wrapper via `(value.payload default value)`, includes `apiName`, `version`, `correlationId`, `timestamp` |
| Liveness DWL | `p-set-liveness-response.dwl` — uses `Mule::p(...)`, includes `apiName`, `version`, `correlationId`, `timestamp`, `status` |
| Retry | `retry.attempts=3` (not 2) |

## Tips

- Run `/use-raml-from-jira` first whenever a JIRA story + Confluence design exist — it auto-generates the `jira-*.md` and `confluence-design-*.md` context files that the develop agent consumes for business logic
- Always provide the RAML spec for accurate connector configuration and DataWeave generation
- If you have a sequence diagram (Mermaid or image), drop it into `project/input_develop/` or paste it in chat — the agent will use it as the primary orchestration structure
- Without a diagram, the agent derives a Mermaid sequence diagram from the Confluence data-flow narrative and asks for your approval before writing any code — review it carefully as it determines the generated flow order
- Store secrets in `~/.zshrc` and reference via `${VAR}` in Maven commands — never pass credentials directly
- The agent also reads all `review-*.mdc` standards during generation to pre-empt review findings
